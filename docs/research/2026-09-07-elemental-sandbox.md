## Bottom line

This is a real, configurable **3D visual-effects playground**, not a generative image model. Its useful ideas are layered visual controls, an immediate preview, reusable presets, and distinct visual identities. For NODEINE, start with a small optional world-atmosphere preview, not the whole combat sandbox behind the feed. Keep the current Next.js application; evaluating this project does not require replacing it with Vite. [Ability registry](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/abilities/AbilityManager.js), [editor](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/ui/Editor.js), [NODEINE package manifest](../../package.json)

## Performance: evidence versus inference

Verified implementation choices:

- A global four-active-cast cap retires the oldest cast; per-type pools retain constructed ability instances. Four active casts does **not** mean only four allocated objects across all ten pools. [Ability manager](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/abilities/AbilityManager.js)
- Particle motion uses shader calculations and instanced geometry. Pixel ratio is capped at 1.75; depth and distortion targets use half resolution. These are meaningful optimizations, not evidence that rendering is free. [Particles](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/particles/ParticleSystem.js), [renderer](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/core/Renderer.js), [post-processing](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/postprocessing/PostProcessing.js#L25-L87)
- The scene still performs multiple rendering passes, bloom/distortion, contact shadows, and a 4096×4096 directional shadow map. Startup prewarms every ability through actual rendering before revealing the scene. The current source explicitly explains why the older compile-only warmup was insufficient, so the README's `compileAsync()`/no-first-cast-stutter statement is not a reliable current guarantee. [Environment](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/world/Environment.js#L77-L96), [current warmup](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/core/App.js#L283-L397), [older README claim](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/README.md#L642-L661)
- The committed `public/` binary assets total **18,251,747 bytes (~17.4 MiB)**, calculated from GitHub's tree sizes. This includes a portrait and is not measured first-load network transfer, compressed delivery, or GPU memory. A separate `dist-baseline` also contains built artifacts and duplicated assets; it should not be mistaken for a freshly verified current production build. [Pinned file tree](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/tree/364c9ce70ba784809291e87981ca83a19560f73d), [asset directory](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/tree/364c9ce70ba784809291e87981ca83a19560f73d/public)

The HUD computes an FPS readout and reports particles, instances, and draw calls. I found no reproducible device/GPU/browser benchmark table or automated benchmark/test script in the inspected README, manifest, and repository tree. **Inference:** the full scene carries materially more rendering and startup work than a small CSS/SVG accent and warrants mobile testing. No measured FPS, battery, temperature, or GPU-memory claim is made here. [HUD measurement](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/ui/HUD.js#L167-L181), [manifest scripts](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/package.json)

## Why it needs adaptation before app integration

These are source-derived risks, not exploited vulnerabilities or live-device results:

1. **Lifecycle:** `App` has stop/dispose methods, but its plain entry point boots once and exposes `window.app`; it supplies no Next/React mount-unmount adapter. Async loading has no cancellation ownership guard, so a wrapper must prevent late load completion from restarting a disposed scene. Disposal also needs scrutiny for individual post passes, shared texture caches, HUD/contact listeners, and timers. [Entry point](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/main.js), [App lifecycle](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/core/App.js), [post disposal](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/postprocessing/PostProcessing.js#L192-L197)
2. **Paused is not stopped:** pause makes simulation time zero, but the animation loop, targeting, controls, and renders continue. The inspected application root has no visibility/offscreen pause or reduced-motion adaptation for the 3D scene. A live effect must stop when hidden/offscreen and release resources on navigation. [Frame loop](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/core/App.js#L431-L529)
3. **Mobile/accessibility:** there is responsive wrapping and pointer input, plus two-touch camera configuration; therefore it is inaccurate to say there is no touch support. However, ability cards are pointer-driven `div`s rather than focusable buttons, aiming requires a pointer, the viewport disables user zoom, and mobile CSS hides the help/stats. The reduced-motion CSS shown only suppresses contact-card effects, not the 3D scene. Rewrite controls as labelled buttons, preserve zoom, add non-pointer actions and a static/reduced-motion mode, and reserve safe-area space. [HUD cards](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/ui/HUD.js#L64-L99), [input](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/input/InputManager.js), [touch camera](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/core/CameraRig.js#L32-L43), [HTML](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/index.html#L1-L15), [responsive/motion CSS](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/ui/styles.css#L929-L975)
4. **Preset safety:** import reads arbitrary-sized JSON without a strict schema; the merge traverses `target[key]` and uses `key in target`, which includes inherited members. Do not reuse that merger for user-shared presets: allowlist own keys, reject prototype-related keys, and cap byte size, nesting, numeric ranges, counts, and strings. Storage failure is also partly swallowed while the editor announces success. NODEINE should reuse its explicit saved/temporary/error pattern instead. [Import/persistence](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/ui/PresetManager.js), [merge](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/config/settings.js#L4475-L4484), [success toast](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/src/ui/Editor.js#L127-L139)
5. **Security scope:** no model-provider or account backend was found in the inspected app. That does not make an unfamiliar dependency tree automatically safe. No dependency audit, binary analysis, or exploit testing was performed; no development server was started. Keep experiments separate from authenticated chat/feed data and never execute imported presets as scripts. [Manifest](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/package.json), [local Vite server configuration](https://github.com/achrefelouafi/LinearAbiltyCastingExtendedThreeJS/blob/364c9ce70ba784809291e87981ca83a19560f73d/vite.config.js)

## Low-cost applications — proposals, not implemented features

The following are design recommendations inferred from the source, not claims about existing features in the other projects. No other project was edited.

| Project | Useful visual idea | Small first implementation |
| --- | --- | --- |
| NODEINE / Forge | World-specific atmosphere and layered preview controls | An opt-in “World atmosphere” preview with three curated presets and controls for palette, intensity, and motion. Start with original CSS/SVG or a cleared short loop; keep the feed and chat static. Store a bounded settings snapshot and offer reset before considering a full shader editor. |
| 108 Yokai — Fourth Portal | Ink tide, ritual rings, restrained ember/void motifs | One original portal entrance or chapter-transition vignette, with a static poster and Skip control. A ritual shape can echo the selected world's artwork without importing the combat system, stranger's avatar, or bundled models. |
| Trinefield portfolio | Interactive demonstration of design judgment | One optional “Play with the atmosphere” hero panel with labelled controls, before/after comparison, and a concise technical explanation. Keep projects, résumé, contact, and navigation immediately available without waiting for WebGL. |
| Biao Chinese site | A controlled brush/ink reveal rather than a game effect | Original SVG mask or brief ink transition beside meaningful content. Keep Chinese text selectable/readable, avoid cultural motifs used without context, preserve mobile zoom, and provide a no-motion presentation. |

The strongest portfolio improvement is not importing thousands of knobs. It is demonstrating a coherent small interaction with understandable controls, responsible rendering cost, clear ownership, and reliable fallbacks. The existing source is best treated as a technical reference and visual vocabulary.

## Suggested validation gate for any later live-3D pilot

1. Agree on one visual, use cleared assets, and keep a static version that conveys the same content.
2. Load only after an explicit preview action; one canvas, one effect, no global full-screen input interception or model credentials.
3. Start without shadow maps, raymarched volumes, or multi-pass bloom; cap density/resolution and then measure whether each extra pass earns its cost. These are proposed budgets, not measured equivalence to the original.
4. Verify stop/dispose during slow loading, rapid navigation, account changes, hidden tabs, WebGL failure, and repeated preview openings; check memory and event-listener growth.
5. Record actual startup time, transfer bytes, frame time, responsiveness, and battery/thermal observations on representative mobile Safari/Chrome hardware. Test keyboard, zoom, reduced motion, contrast, and error/permission states independently.
6. Keep reference-guided image generation a separate Forge capability. A procedural effect preset cannot substitute for an image model or guarantee reference fidelity.
