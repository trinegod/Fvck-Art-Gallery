# Design-tool audit — September 7, 2026

## Recommendation

Keep `design-system-synthesis` and each app's own approved `DESIGN.md` as the decision-making layer. Consider Impeccable for bounded critique, accessibility/responsive audits, and hardening. Use UI UX Pro Max as a targeted local reference library, not a replacement identity generator. Anthropic frontend-design supplies useful art-direction principles but adds the least to our existing skill; the license situation at the exact supplied plugin path needs clarification before copying it into a reusable skill.

Do not install all three globally: their broad frontend triggers overlap, their defaults can disagree, and the current packages have more side effects than a collection of Markdown prompts.

## 1. Impeccable: strongest incremental review capability, largest runtime footprint

### What it actually provides

The current README describes one routed skill, 23 commands, live browser iteration, and 61 deterministic detector rules. The inspected skill distinguishes task-oriented interfaces, reading surfaces, persuasive surfaces, and artifact-led experiences; this is more useful than applying one visual style to a whole product. It preserves the incumbent identity for refinements and separates product facts in `PRODUCT.md` from visual decisions in `DESIGN.md`. There is already an explicit Codex skill payload under `.agents/skills/impeccable`. [README](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/README.md), [actual skill](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/.agents/skills/impeccable/SKILL.md).

This is **not merely an aesthetic prompt pack**. Rust checks implement concrete border-pattern detection and contrast calculations, including different thresholds for large text and context handling. The audit playbook adds model-led checks across accessibility, performance, theming, responsiveness, and implementation integrity. Its audit is explicitly report-only; other commands perform changes. The numerical health score is a tool-specific heuristic, not accessibility certification or user-research evidence. The repository itself warns that a clean detector run cannot prove visual or accessibility quality. [Rule implementation](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/crates/core/src/checks/rules.rs), [audit playbook](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/.agents/skills/impeccable/reference/audit.md), [detector limitations](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/README.md#cli).

### Portability, dependencies, and side effects

- Codex is an explicit provider mapped to `.agents`; use its provider-specific artifact rather than a Claude copy. Full operation includes engine commands and optional agent handoffs, not only reading Markdown. [Provider mapping](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/crates/skills/src/providers.rs).
- The npm wrapper declares Node `>=22.18.0` and platform-specific optional binary packages. The skill launcher can run an existing native binary without Node; otherwise it downloads its pinned binary into the user cache and verifies a SHA-256 sidecar before executing it. A checksum from the same release channel is integrity checking, not an independent security audit. [Package](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/package.json), [launcher](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/.agents/skills/impeccable/scripts/impeccable).
- Install/update can add provider-native edit/Stop hooks; the README describes a default-yes interactive hook offer, per-developer settings, and a `--no-hooks` option. Subsequent use writes `.impeccable/` state, screenshots, configuration, surface briefs, and review artifacts. Live mode can wire into a local development app and run an optional project-defined validation shell command. Production live injection is explicitly unsupported. [Hook and live-mode documentation](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/README.md#design-hook).
- Packaging verification is necessary: the audited root `.codex/hooks.json` points to `.codex/skills/impeccable`, while the README/provider mapping describes `.agents/skills`. This does not establish that generated release installation is broken, but makes blind copying of that root manifest unsafe. Inspect the actual installed paths before enabling hooks. [Root hook file](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/.codex/hooks.json).

License: Apache-2.0 at the root; a NOTICE identifies MIT-derived native-platform reference material. Preserve applicable license/notice material if copying or adapting the package. [LICENSE](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/LICENSE), [NOTICE](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/NOTICE.md).

### Fit and conflict with the existing skill

The existing `design-system-synthesis` already owns product evidence, originality, semantic tokens, states, motion, responsive behavior, and bilingual/regional gates. Impeccable's incremental value is its named review vocabulary, measurable detector, and surface-specific workflows. Its craft-floor preferences are not universal UX laws: it prescribes particular radius ranges and contains an absolute ban on eyebrow labels, despite broader brief-first language. Treat these as editorial opinions, never reasons to undo an approved project decision. [Craft floor](https://github.com/pbakaus/impeccable/blob/ea8bfc1d99fd8e53c9a9e538e90bf25f30c127f6/.agents/skills/impeccable/reference/craft-floor.md).

**Recommendation:** pilot one report-only audit or critique on a known local screen. No hooks, live wiring, global installation, or autonomous `DESIGN.md` replacement in the first pilot. Promote only useful, verified findings into the project contract.

## 2. Anthropic frontend-design: concise art-direction guidance, limited incremental value

The exact plugin subtree contains a README, a plugin manifest, and one skill file—no bundled detector, scripts, token database, or test runner. The skill asks for subject-specific visual decisions, a compact token/layout plan, review against the brief, restrained motion, clear interface copy, and self-critique. It now expressly allows an already-pinned look even when that look resembles a common generated default. These are useful principles, but the README's production-quality claims describe intended model output, not a verifiable capability or guarantee. [Plugin subtree](https://github.com/anthropics/claude-code/tree/ab9b2cf7bb9e4f98ff264c07a22e46d83c29c558/plugins/frontend-design), [skill](https://github.com/anthropics/claude-code/blob/ab9b2cf7bb9e4f98ff264c07a22e46d83c29c558/plugins/frontend-design/skills/frontend-design/SKILL.md), [README](https://github.com/anthropics/claude-code/blob/ab9b2cf7bb9e4f98ff264c07a22e46d83c29c558/plugins/frontend-design/README.md).

**Codex portability:** the procedural ideas do not require Claude-specific tools, but the supplied `.claude-plugin` manifest is not a Codex installation artifact. Porting the text is technically straightforward only after rights and trigger conflicts are resolved; it would add little beyond the existing synthesis skill's audience-first, original-identity workflow. Nothing inspected establishes that a separate model, paid design service, or asset-generation API is included.

**License finding:** the skill frontmatter points to `LICENSE.txt`, but the audited plugin subtree contains no such file. The repository root `LICENSE.md` reserves rights and refers to Anthropic's Commercial Terms. Therefore do **not** describe this exact supplied plugin as MIT/Apache licensed or automatically safe to vendor. A similarly named skill in another Anthropic repository is a different source and should receive its own pinned license check; its license must not be silently transferred here. This is a source discrepancy, not a legal opinion. [Skill license pointer](https://github.com/anthropics/claude-code/blob/ab9b2cf7bb9e4f98ff264c07a22e46d83c29c558/plugins/frontend-design/skills/frontend-design/SKILL.md), [repository license](https://github.com/anthropics/claude-code/blob/ab9b2cf7bb9e4f98ff264c07a22e46d83c29c558/LICENSE.md).

**Recommendation:** retain it as a cited comparative reference for original art direction. Do not install or copy it just to duplicate our existing design skill.

## 3. UI UX Pro Max: broad searchable reference data, not a standalone AI designer

### What is substantiated

The core is standard-library Python: CSV loading, BM25 lexical ranking, category matching, and rule application. The design-system generator aggregates matching product/style/color/typography/landing records, applies deterministic decisions, and formats output; the host coding agent supplies the generative intelligence. It is not a new trained design model or an independent API-backed reasoning service. Optional density, variance, and motion parameters alter recommendation selection/output. [Search core](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/src/ui-ux-pro-max/scripts/core.py), [generator](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/src/ui-ux-pro-max/scripts/design_system.py).

The committed catalog summary records 79 searchable styles (50 active), 192 product/palette/reasoning profiles, 74 font pairings, 119 UX guidelines, and 22 stacks. These are corpus inventory counts, not evidence that every recommendation fits a product or meets accessibility requirements. Version-aware stack filtering is implemented, but its current Next.js applicability string is 16.2; NODEINE uses 16.3.3, so local installed Next.js documentation still wins. [Catalog summary](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/src/ui-ux-pro-max/data/catalog-summary.json), [stack configuration](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/src/ui-ux-pro-max/scripts/core.py).

Its skill appropriately recommends narrow queries, verifying the returned category, one bounded retry, and honest fallback labeling. Nevertheless the generator contains generic default typography, colors, and landing-page structures when particular matches are absent. Do not treat a formatted result as a validated design system. [Skill query contract](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/.claude/skills/ui-ux-pro-max/SKILL.md), [generator defaults](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/src/ui-ux-pro-max/scripts/design_system.py).

### Portability and installation scope

- The Codex template explicitly targets `.agents/skills/ui-ux-pro-max`; rendering adds the correct project/global path prefix. The Claude copy uses a Claude plugin environment variable and should not simply be pasted into Codex. [Codex template](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/src/ui-ux-pro-max/templates/platforms/codex.json), [renderer](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/cli/src/utils/template.ts).
- Core search requires Python 3 and no external Python packages; ordinary search does not need network access. The installer is separate Node tooling with `chalk`, `commander`, `ora`, and `prompts`. It normally copies bundled templates; its legacy mode can fetch a GitHub release. [README prerequisites](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/README.md#prerequisites), [CLI package](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/cli/package.json), [installer](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/cli/src/commands/init.ts).

Those siblings include additional executable scripts; the core search's no-dependencies/no-network statement must not be generalized to every bundled capability. Existing skill paths are skipped unless forced, but that is still a broader install than one lookup tool. [Installer's sibling-copy logic](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/cli/src/utils/template.ts), [bundled sibling inventory](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/tree/4aad0584d92131626b16d4ff4d77f0455385013c/cli/assets/skills).
- Persistence writes `design-system/<project-slug>/MASTER.md` and page overrides; its skill protects existing content unless explicit force is authorized. This creates another authority hierarchy alongside NODEINE's `DESIGN.md`; avoid two competing sources of truth. Font-pairing records can suggest Google Fonts CSS imports, and motion output can suggest GSAP snippets—neither is permission to add runtime dependencies. [Persistence workflow](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/4aad0584d92131626b16d4ff4d77f0455385013c/.claude/skills/ui-ux-pro-max/SKILL.md).

License: repository MIT, with copyright and permission notice retention required for copied/substantial material. Referenced font/icon assets still need their own applicable license review. **Recommendation:** use selected UX, component, and stack queries as secondary evidence, then verify consequential technical advice against primary docs. ## Durable UX guidance to retain

1. **One approved contract per app.** Product facts, semantic tokens, interaction states, localization, motion, and verification criteria should survive the chat. Supplement `DESIGN.md` with linked surface notes only when necessary; do not silently create a competing generated master.
2. **Choose by the screen's job.** Gallery viewing, chat operations, reading, and portfolio persuasion need different densities and emphasis inside the same identity.
3. **Separate measurable defects from taste.** A keyboard trap, lost state, unreadable text, or overflow is not equivalent to disliking a font or radius. Record impact, reproduction evidence, and severity before changes.
4. **Protect approved identity and real content.** References supply principles; they do not justify copying a brand, replacing artwork, inventing claims, or chasing novelty.
5. **Test the uncomfortable states.** Loading, empty, error, disabled, interrupted, uncertain delivery, expired access, long labels, zoom, mixed Latin/CJK text, and reduced motion belong in acceptance criteria—not a final cosmetic pass.
6. **Keep reviews bounded and evidence-backed.** Inspect representative mobile/desktop screens and key keyboard paths, group fixes, then confirm. Expand testing when a material defect requires it; a numeric tool score is not the release gate.
7. **Treat installation as a separate decision.** Pin the exact artifact, inspect license and writes, preserve backups, verify path/trust behavior, and disable broad automation initially. No global installs or package execution occurred in this audit.

Open questions before adoption: actual release-package parity with the audited commits; the Anthropic license pointer; Impeccable's generated Codex hook path/trust behavior; and whether either tool produces useful incremental findings on one of our real screens.
