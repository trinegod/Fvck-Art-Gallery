# Domain documentation

Use the single-context layout: root `CONTEXT.md` and `docs/adr/`.
Before domain exploration, read the glossary and any ADR relevant to the work.
If a root `CONTEXT-MAP.md` later exists, follow it to the relevant context instead.

Missing domain files are not blockers. Create them lazily as terminology or
qualifying decisions are resolved through the domain-modeling workflow.
Use the glossary's terms consistently and surface conflicts with an ADR before
proposing a contradictory change. Keep tracker specs and tickets canonical;
the local project index links to them rather than duplicating their contents.
